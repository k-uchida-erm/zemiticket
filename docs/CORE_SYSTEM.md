# Core System (Concept)

このドキュメントは Zemiticket の「仕組みの根幹」を、技術詳細ではなく概念として説明します。

## 1. 何があるか（登場人物と箱）
- Workspace（ワークスペース）
  - 研究室という「箱」。今は1つだけを前提に運用。
- Owner（オーナー）
  - 研究室の責任者（先生）。Sidebarの研究室名の下に表示。
- Members（メンバー）
  - 学生・スタッフ。学年（B3/B4/M1/M2/D1/D2/D3）でグルーピングして表示。
- Research Topics（研究テーマ）
  - 研究室の活動テーマ。色（Color）を持つ。Sidebar と Home の帯で使う。
- Tickets（チケット）
  - 仕事・タスク・研究活動の単位。無限階層（親子自己参照）。担当者（Assignee）と所属テーマを持てる。

## 2. どう見えるか（画面の原則）
- Sidebar（左）
  - 上から Workspace 名 → Owner 名 → Account（自分） → Research Topics → Members（学年別）。
- Home（中央）
  - 研究テーマごとの「灰色の帯」でグループ化。
  - それぞれの帯の下に、そのテーマに属する「親チケット」一覧（子はネスト展開）。
  - 上部のフィルターで「MY / ALL」を切り替え。

## 3. 役割と責務
- Owner
  - メンバー/テーマの全体を俯瞰し、運用の責任を持つ。
- Member（Assignee）
  - 自分に割り当てられたチケットを遂行。Home の MY で自分の担当のみを確認可能。
- Workspace
  - 研究テーマ・メンバー・チケットを包含する最上位の入れ物。

## 4. チケットのルール
- 単一の「Ticket」型（親子の自己参照で階層化）。
- 1つのチケットは以下を持てる：
  - 所属テーマ（Research Topic）
  - 担当者（Member）
  - 親チケット（なければ親）
  - ステータス（todo / in_progress / review / done）
- 表示原則：
  - Home は研究テーマごとに「親チケット（level=0）」を並べる。
  - 子チケット（level≥1）は親の下に展開して表示。
  - MY は担当者が自分のものだけ、ALL は全員分を表示。

## 5. ステータスの意味（UIアイコン準拠）
- todo：未着手（薄いグレーの丸）
- in_progress：進行中（オレンジ丸＋白いピン）
- review：査読/確認中（青丸＋白の目アイコン）
- done：完了（緑丸＋白い角張りチェック）

## 6. 研究テーマ（帯）の意味
- 研究室の活動を意味的に束ねる単位。
- 帯の左に色の丸。テーマごとに色を割り当て、一覧の視認性を上げる。

## 7. フィルターの原則
- MY：自分に割り当てられたチケットのみ。
- ALL：ワークスペース内の全チケット。
- 帯の中のタブ（All / To do / In progress / In Review / Done）で、その帯内の表示を絞り込み。

## 8. 命名と粒度
- チケットのタイトルは「誰が見ても分かる粒度」。
- 親チケットはテーマの進捗を表す看板、子は実行単位。必要に応じて更にネスト可。

## 9. 初期セットアップ（運用観点）
1) Workspace を作る（今は1つ前提）
2) Owner を決める（先生）
3) Members を登録（学年付き）
4) Research Topics を決めて色を設定
5) 親チケットをテーマごとに用意 → 必要に応じて子を追加

## 10. 権限と可視性（MVPの前提）
- MVPでは全員が全テーマ・全チケットを閲覧可能。
- MY は「自分の担当」を抽出する見せ方（権限制御ではない）。
- 厳密な閲覧制御が必要になれば、将来ワークスペース権限/ロールで拡張。

## 11. 将来拡張の入口
- 認証（ログイン後のみ閲覧）
- 担当変更・ステータス更新のワークフロー
- 通知（右の通知/カレンダーはMVPでは非表示）
- テーマ横断での横串ビュー（ガント/カンバン など）

この概念に基づいて、技術的な実装（API/DB/フロント）は最小構成で組まれています。

## 12. ユーザー利用フロー（アカウント〜ワークスペース参加）

ここでは、実運用を想定した非技術的な「利用の流れ」を示します。

1) アカウント作成（ロール選択）
   - アカウント作成時に「先生」か「生徒（メンバー）」を選択。
   - 生徒はプロフィールに「氏名・学年」を設定。

2) ワークスペースの作成（先生のみ）
   - 先生（Owner）が初回ログイン後に研究室用のワークスペースを作成（名称と説明を入力）。
   - 先生はそのワークスペースの Owner として登録される。

3) 生徒の参加（検索→参加）
   - 生徒はログイン後、「ワークスペース検索」で先生のワークスペースを探す（研究室名/先生名で検索）。
   - 見つかったワークスペースに「参加」する（即時参加 or 先生承認制は運用に応じて設定）。
   - 参加時点で「学年」がメンバー情報に反映され、Sidebar に学年ごとに表示される。

4) 研究テーマの準備（先生または担当者）
   - 研究テーマ（Research Topic）を用意し、わかりやすい表示名と色を設定。
   - テーマは Sidebar と Home の帯で可視化される。

5) チケットの作成（親→子の順で）
   - 親チケット（研究テーマの看板）を作る → 必要に応じて子チケットを追加。
   - 担当者（Assignee）を設定して、MY で自分の担当が見えるようにする。

6) 日々の運用
   - 学生は MY で自分の担当チケットを確認・更新。
   - ALL で研究室全体の進捗を俯瞰。先生はテーマ別の状況を把握。
   - ステータス（todo/in_progress/review/done）で進行状況を合わせる。

7) 学期・年度切替時
   - 研究テーマは継続。必要に応じて新入生を追加し既存テーマに参加。
   - 終了チケットは done、継続案件は親に残し新しい子を追加。
